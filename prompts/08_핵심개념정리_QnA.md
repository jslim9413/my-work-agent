# 2부 4교시 — 핵심 개념 정리 및 질의응답

## 1. 1부 + 2부 전체 그림 (한 장 요약)
```
[사용자 브라우저/휴대폰]
        │ 링크 접속 (https://○○.streamlit.app)
        ▼
[Streamlit Community Cloud]  ◀── 자동 배포 ── [GitHub 저장소] ◀── git push ── [내 PC + Claude Code]
   streamlit_app.py (화면)
        │ 부른다
        ▼
   Agent (1부)  ── 날짜 계산·파일 찾기는 파이썬 코드
        │ 질문 + 고른 문서
        ▼
   [OpenRouter API] ──▶ LLM (gpt-4o-mini 등)
   ▲ API 키는 Secrets 에만 보관
```

## 2. 핵심 개념 12가지
| # | 개념 | 한 줄 정의 | 비유 |
|---|---|---|---|
| 1 | LLM | 글을 읽고 다음 글을 만들어내는 AI 모델 | 아주 박식한 신입사원 |
| 2 | 프롬프트 / 시스템 프롬프트 | AI에게 주는 지시문 / 항상 지켜야 할 기본 규칙 | 업무 지시서 / 회사 규정 |
| 3 | 컨텍스트 | AI에게 함께 건네주는 자료 | 회의 전에 나눠주는 자료 |
| 4 | 환각 | 자료에 없는 내용을 그럴듯하게 지어내는 현상 | 모르는데 아는 척 |
| 5 | 도구 호출 (function calling) | AI가 "이 함수를 이 값으로 실행해줘"라고 요청하는 방식 | 신입이 "이 계산은 엑셀로 할게요" |
| 6 | Agent | 도구를 고르고, 결과를 보고, 다시 판단하는 반복 구조 | 스스로 일 순서를 정하는 비서 |
| 7 | Streamlit | 파이썬만으로 웹 화면을 만드는 라이브러리 | 파워포인트처럼 쉽게 만드는 웹 화면 |
| 8 | rerun / session_state | 조작할 때마다 파일 전체 재실행 / 그래도 남는 기억 상자 | 매번 새로 쓰는 칠판 / 칠판 옆 메모장 |
| 9 | 로컬 vs 배포 | 내 PC에서만 실행 vs 인터넷 서버에서 실행 | 집에서 연습 vs 무대 공연 |
| 10 | GitHub / git push | 코드 보관소 / 내 PC의 변경을 보관소로 올리기 | 공유 드라이브 / 업로드 |
| 11 | Secrets / .env | 코드 밖에 따로 두는 비밀 값 | 금고 (코드는 진열장) |
| 12 | API 비용·한도 | 쓴 만큼 내는 요금, 키별 상한 | 법인카드 + 한도 |

## 3. 3문항 확인 퀴즈 (구두로)
1. 버튼을 누를 때마다 숫자가 0으로 돌아간다. 무엇을 써야 할까? → `st.session_state`
2. API 키를 GitHub 에 올리면 안 되는 이유와, 대신 넣는 곳은? → 공개 저장소면 누구나 키를 쓸 수 있음 / Streamlit Secrets
3. 앱 화면 글자를 고쳤는데 배포된 앱에 반영하려면? → 커밋 후 git push (자동 재배포)

## 4. 예상 질문과 답
| 질문 | 답 |
|---|---|
| 회사 실제 문서로 써도 되나요? | 무료 클라우드는 서버가 미국에 있고 공개 저장소가 기본이라 **샘플·공개 가능한 자료만**. 실제 문서는 로컬 실행(`streamlit run`)으로만 쓰거나, 회사 승인을 받은 사내 서버·유료 클라우드를 검토하세요. |
| 링크를 받은 사람이 내 문서를 볼 수 있나요? | 앱 화면에서 보여주는 문서는 볼 수 있고, 공개 저장소면 GitHub 에서 파일도 볼 수 있습니다. 그래서 비밀번호와 샘플 데이터를 씁니다. |
| 비용이 얼마나 나오나요? | Streamlit Cloud 는 무료, AI 호출만 OpenRouter 요금(gpt-4o-mini 기준 질문 1회에 1원 안팎~수 원 수준으로 예상). 키에 Credit limit 를 꼭 걸어두세요. |
| 앱이 "Zzzz" 라며 잠들어 있어요 | 12시간 동안 방문자가 없으면 잠듭니다. 깨우기 버튼을 누르면 다시 켜집니다. 발표 직전에 한 번 열어두세요. |
| 무료 모델로 바꿔도 되나요? | `LLM_MODEL` 만 바꾸면 됩니다. 단, **도구 호출(tools)을 지원하는 모델**이어야 Agent 가 동작합니다. |
| 다른 사람도 각자 자기 파일을 올려 쓰게 할 수 있나요? | 가능하지만 사용자별 저장 공간·로그인 기능이 필요해 오늘 범위를 넘습니다. `st.file_uploader` 로 "올린 파일에만 질문하기"부터 시작해 보세요. |
| 휴대폰에서도 되나요? | 네. Streamlit 화면은 휴대폰 화면에 맞게 자동으로 배치됩니다. |
| 회사 메신저나 이메일과 연결할 수 있나요? | 가능합니다. 슬랙·메일 API 를 도구로 하나 더 추가하는 방식이며, 다음 단계 과제로 추천합니다. |
| Streamlit 말고 다른 방법은? | Gradio(AI 데모에 특화), Hugging Face Spaces(배포), 정식 웹서비스는 React + 백엔드. 업무용 내부 도구는 Streamlit 이 가장 빠릅니다. |
| 코드를 하나도 모르는데 계속 고칠 수 있나요? | 오늘처럼 "무엇을, 어디에, 어떻게 확인" 을 적어서 Claude Code 에 지시하면 됩니다. 에러 메시지는 그대로 붙여넣으세요. |

## 5. 다음 단계 과제 (선택)
```
my_app.py 에 '📤 파일 올리기' 탭을 추가해줘. st.file_uploader 로 .md .txt .docx 를 올리면
그 파일 내용에 대해서만 질문할 수 있게 해줘. 올린 파일은 서버에 저장하지 말고 메모리에서만 다뤄.
```

```
매일 아침 9시에 '오늘 일정 + 오늘 마감 할 일'을 요약해서 보여주는 '아침 브리핑' 카드를
앱 첫 화면 맨 위에 추가해줘. AI 호출은 버튼을 눌렀을 때만 하도록.
```
